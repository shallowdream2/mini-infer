## Roofline 分析

RTX 4090 参数：Peak FP16 ~82 TFLOPS（tensor core），内存带宽 ~1008 GB/s，ridge point ≈ 82 FLOPs/Byte。

所有配置的算术强度 AI ≈ 6.7–7.0 FLOPs/Byte，**远低于 ridge point 82，均为 memory-bound**。

理论极限（BW bound）：
- flash_attn 实际延迟 / BW bound = 11.7 μs / 0.27 μs ≈ **43×（batch=1, seq_len=128）**
- Triton 实际延迟 / BW bound = 14.3 μs / 0.27 μs ≈ **53×**
- 表明两者都远未达到硬件内存带宽上限，kernel launch overhead 和内存访问模式是主要瓶颈

---

## 性能差距根因分析

**Triton 首版 vs flash_attn 差距（1.23×–9.46×）：**

| 根因 | 说明 |
|------|------|
| **seq_len 较短时差距小（1.23×）** | kernel launch overhead 占比高，seq 增大后差距体现在内存访问模式 |
| **seq_len 增大后差距扩大** | Triton 首版无向量化 global memory load（逐元素 float16），flash_attn 使用 float4 向量化访问；seq_len 越大，KV 读取量越多，差距越明显 |
| **无 K/V 预取流水线** | Triton 的 K/V load 与 computation 串行，flash_attn 通过 prefetch 隐藏内存延迟 |
| **GQA grid 设计**：28 个 Q heads × batch | 每个 Triton program 独立处理一个 (batch, q_head) pair，cache line 复用率低；flash_attn 针对 GQA 有专门优化 |

**batch=8 时差距缩小（2.6×–3.1×）：**
- batch 增大使 KV 读取量增加，GPU 有更多并行任务，隐藏了 Triton 的 kernel launch 开销和部分访存延迟

---

## 结论

1. **正确性**：Triton kernel 数值正确，max_diff ≤ 1.5e-5，满足 < 1e-2 验收标准 ✅
2. **性能**：Triton 首版在 seq_len=128 时接近 flash_attn（1.23×），随 seq_len 增大差距扩大（最大 9.46×），符合预期（首版实现无向量化优化）
3. **定性结论**：Triton kernel 实现路径通畅，性能差距的根因清晰（向量化访存、prefetch 流水线），为后续优化提供了明确方向
4. **局限性**：本次测试使用 dense KV tensor，未测试 paged KV（block_table 路径）；seq_len 上限 2048，更长序列未测试
