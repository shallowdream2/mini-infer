# Phase 12.5 开发日志：Flash Decoding（Split-K Attention）

日期：2026-03-22

---

## 做了什么

Phase 12.5 目标是实现 Flash Decoding（split-K）Triton kernel，解决 Phase 6.5 Triton kernel 的 SM 利用率不足问题（batch=1 时 1.5B 只有 12 thread block，RTX 4090 利用率 ≈ 9%）。

实现分三步：
1. 新建 `mini_infer/triton_flash_decode.py`：split kernel（Triton JIT）+ reduce（PyTorch）+ 公开接口
2. 新建 `tests/test_flash_decode.py`：21 个测试（正确性、GQA、空 split、非整除 seq_len）
3. 新建 `benchmarks/benchmark_flash_decode.py`：seq_len sweep，4 路径对比

## 关键决策

**两阶段架构（split Triton + reduce PyTorch）**：原设计想写两个 Triton kernel，但 reduce 阶段在 num_splits ≤ 32 的条件下，PyTorch 的 exp/sum 开销 < 0.01ms，远小于编写和调试 Triton reduce kernel 的代价。选择 PyTorch reduce，可读性高，性能损失可以忽略。

**`range(split_start, split_end, BLOCK_N)` 运行时边界**：担心 Triton 2.1.0 不支持运行时 range 边界，但测试通过说明是支持的（step 为 constexpr，start/end 可以是运行时值）。

**auto_num_splits 策略**：`min(seq_len // BLOCK_N, ceil(sm_count / (batch * num_q_heads)))`。1.5B 锁定 11 splits（刚好让 132 个 thread block 覆盖 128 SM），7B 锁定 5 splits（28 heads 已能覆盖更多 SM）。

## 卡在哪里

**Triton 2.1.0 的两个兼容性问题**（review 前没有发现，第一次运行测试时报错）：

1. `tl.ones([1], dtype=tl.float32)` → `AttributeError: module 'triton.language' has no attribute 'ones'`
   修复：`tl.full([1], 1.0, dtype=tl.float32)`

2. `tl.store(pl_base, lse)` → `ValueError: Value argument cannot be block type if pointer argument is not a block`
   `pl_base` 是标量 pointer，`lse` 是 `[1]` block tensor，类型不匹配。
   修复：`tl.store(pl_base + tl.arange(0, 1), lse)` 将 pointer 也变成 `[1]` block。

## 意外发现

**flash_attn 对比目标过于激进**：原计划 "seq_len=4096 < 0.5× flash_attn"，实测约 5.7× 慢。根因是 flash_attn 是 CUDA C++（warp-level + SMEM tiling），Triton 实现走 L2 cache，实现层级不同。有意义的对比是 vs Phase 6.5 triton_65，在此维度 split-K 的 3.31× 加速是实质性收益。

**延迟平坦性是核心结果**：seq_len 从 128 增到 4096（32×），flash_decode 延迟从 0.064ms 到 0.068ms（+6%），而 triton_65 从 0.021ms 到 0.224ms（+967%）。这比任何 speedup 数字都更能说明 split-K 的意义。

## benchmark 结果摘要

- 1.5B bs=1 seq=2048: triton_65 0.112ms → flash_decode 0.070ms (**1.60×**)
- 1.5B bs=1 seq=4096: triton_65 0.224ms → flash_decode 0.068ms (**3.31×**)
- 7B bs=1 seq=4096: triton_65 0.256ms → flash_decode 0.100ms (**2.57×**)
- vs flash_attn: 约慢 5-7×（实现层级差距，非算法问题）
