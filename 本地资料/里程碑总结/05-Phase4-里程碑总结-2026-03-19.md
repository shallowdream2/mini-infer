# Phase 4 里程碑总结：双卡扩展（Replica + HF Pipeline Parallel）

本文件记录 mini-infer Phase 4 的完整实现过程、关键决策、benchmark 数据和阶段结论。

---

## 背景与目标

Phase 3 在单卡上将 batch=8 throughput 从 Phase 2 的 49.1% HF 提升到 88.4% HF（361 tok/s），已基本接近单卡上限。Phase 4 目标是评估两种双卡扩展策略，并通过真实 benchmark 验证其收益与代价。

**目标**：
1. **Replica（数据并行）**：两块 GPU 各跑一个完整 LLMEngine，round-robin 分发请求，验证 ~2× 吞吐是否可达
2. **TP=2（HF Pipeline Parallel）**：用 `device_map="balanced"` 将模型层分布到两卡，评估单卡显存减半的代价与收益

**验收标准**：
- `ReplicaEngine` dry_run 测试通过，真实双卡 benchmark 可运行
- `TPEngine` 无警告加载，真实双卡 benchmark 可运行
- 有三模式（single/replica/tp2）对比数据

## 关键成就

### benchmark 数据（batch=8，max_new_tokens=128，RTX 4090 × 2）

| 模式 | Throughput | TTFT（近似）| Peak Mem GPU0 | Peak Mem GPU1 |
|------|-----------|-------------|---------------|---------------|
| single（Phase 3 基线）| 361.4 tok/s | 19.4 ms | 16.42 GB | — |
| replica（双卡数据并行）| 376.1 tok/s | 23.1 ms | 16.31 GB | 16.31 GB |
| tp2（HF Pipeline Parallel）| 361.5 tok/s | 21.4 ms | 7.00 GB | 8.97 GB |

### 核心发现

**1. Replica 在 batch=8 规模下收益极小（+4.1%），原因是 batch 太小**

batch=8 → 每卡 4 条请求。Phase 3 数据：单卡 batch=4 = 194.2 tok/s。两卡并发 batch=4 的理论上限为 388 tok/s，实测 376 tok/s（96.9% 效率）。但单卡 batch=8 已达 361 tok/s，因此 replica 的增量只有 4%。Replica 的真正价值场景是总请求量超出单卡最优 batch（如 16+ 条）或单卡 KV 显存不足时。

**2. tp2 吞吐与单卡持平，主要收益是每卡显存减半**

Pipeline Parallel 是层间串行，总计算量不变，吞吐与单卡无本质差异。真正的价值场景是 70B 级别大模型（单卡 24 GB 装不下）。对于 Qwen2.5-7B 这类单卡可以装下的模型，tp2 没有吞吐收益。

**3. 工程设计决策验证**：TPEngine 不集成自定义 KV cache 是正确选择

Pipeline Parallel 下每层 KV 在各自 GPU，与 `KVCacheManager` 的单设备 block pool 不兼容。集成代价极高且无吞吐收益，"测量用引擎"的设计定位是合理的。

## 问题与风险

### 已解决

1. **HF cache 不完整触发重下载**：snapshot 子目录只有 shard 1 软链接，用根目录路径 + `HF_HUB_OFFLINE=1` 绕过。已写入环境配置文档和记忆。
2. **TPEngine 右填充**：tokenizer 默认右填充导致 decoder-only 生成质量下降，修复为 `padding_side="left"`。
3. **review 越界修复**：infer-review 阶段直接改了代码（不应该），已记录为行为反馈，后续 infer-review 只列问题。

### 已知局限

1. **Replica 未测大 batch**：batch=8（每卡 4）不能体现 replica 的真实 scaling，需要 batch ≥ 16 才能看到接近 2× 的收益。PROMPTS 列表只有 8 条，目前无法直接测 batch=16。
2. **P2P 驱动旧版**：accelerate 多卡通信可能有额外延迟，建议升级驱动后复测。
3. **tp2 未真正测 PP 延迟优势**：批推理下 PP 无吞吐优势，但延迟密集场景（单请求超长序列）可能有不同表现，未测。
4. **tp2 生成质量未验证**：右填充修复已提交，但修复后未在 GPU 上重新跑一次确认。
