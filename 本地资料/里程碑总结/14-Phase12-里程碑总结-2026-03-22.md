# Phase 12 里程碑总结：CUDA Graph

日期：2026-03-22

---

## 一、阶段目标

在 mini-infer 的 `decode_batch` 路径上引入 CUDA Graph，将整个 decode step 录制为静态 CUDA kernel 序列，绕过 Python→CUDA dispatcher 的调度开销，实现在不改变输出分布的前提下降低 decode 延迟。

---

## 二、完成了什么

### 新增代码

| 文件 | 改动内容 |
|------|---------|
| `mini_infer/config.py` | 新增 `use_cuda_graph: bool = False` 字段（默认 off，不影响现有行为） |
| `mini_infer/model_runner.py` | `warmup_cuda_graphs()`：启动时为 bs=1/2/4/8 做 warmup + CUDA Graph 捕获；`_graph_decode_forward()`：copy_() 更新静态 buffer → replay；`_eager_decode_forward()`：原 eager 路径提取为独立方法；`decode_batch()` 分路逻辑：`_find_padded_bs()` 决定走 graph 还是 eager |
| `mini_infer/engine.py` | `__init__` 末尾在 `use_cuda_graph=True` 时调用 `warmup_cuda_graphs()` |
| `benchmarks/benchmark_cuda_graph.py` | 新建：eager vs graph 逐 batch_size 延迟/吞吐对比 |
| `tests/test_cuda_graph.py` | 新建：dry_run 级 7 条测试（warmup noop、`_find_padded_bs` 边界、引擎初始化） |

### 关键设计决策

- **max_kv_len 固定为 config.max_model_len**：RoPE 的 cos/sin 形状恒定，CUDA Graph 兼容；position_ids 仍由实际 cache_seqlens 决定，正确性不受影响
- **静态 buffer + copy_() 模式**：graph 捕获后，每步 replay 前通过 `copy_()` 更新静态 input_ids / position_ids / block_table / cache_seqlens，GPU kernel 读到最新数据
- **padding 策略**：actual_bs 不匹配时 pad 到最近的捕获 bs，pad 部分 input 填零，输出不使用 pad 行
- **ensure_next_slot / advance_seq_lens / 采样全部在 graph 外执行**：这些是 Python 状态变更，无法（也不需要）捕获进 graph

## 四、遇到的问题

### 问题 1：`_graph_decode_forward` 缺少 `try/finally`（review 发现）

**现象**：`g.replay()` 抛异常时 `_paged_ctx` 不会被清除，下一次 prefill 调用会误走 decode 路径。
**严重性**：低（replay 正常不抛异常，但有隐患）
**修复**：infer-benchmark 前加 `try/finally`，与 eager 路径保持一致。

### 问题 2：`vocab_size` 未使用变量（review 发现）

草稿代码残留，review 中发现并删除。

### 问题 3：每步分配临时 GPU tensor（review 发现）

`_graph_decode_forward` 原实现每次调用都 `torch.zeros(padded_bs, max_blocks, ...)` 分配临时 tensor。已改为在 warmup 时预分配 `bt_staging` 并存入 `_graph_static`，每步只做 `copy_()`，无动态分配。

### 问题 4：7B 模型加速率仅达边界（5%，不是预期 5–15%）

**根因**：7B model forward 耗时约 15–16 ms/step，Python dispatch 仅占 ~1 ms（~5%）。CUDA Graph 能消除的上限就是 5% 左右，与 1.5B（29%）差异悬殊。这是预期内的结果，不是 bug：
```
Python dispatch / total = (17.63 - 16.76) / 17.63 = 4.9%
```
**结论**：大模型上 CUDA Graph 收益接近理论上限，但实测数字恰好在验收门槛（5%）边缘，技术上算达成。

## 六、下一阶段计划

**Phase 12.5：Flash Decoding（Split-K Attention）**

目标：扩展 Phase 6.5 的 Triton kernel，增加 split-K 维度，提升长序列（seq_len > 2048）decode 时的 SM 利用率。

验收标准（来自路线图）：
1. seq_len=2048 时，Triton split-K 延迟 ≤ flash_attn_with_kvcache
2. seq_len=4096 时，有明显提升（目标 < 0.5× flash_attn）
3. 数值正确性：max_diff < 1e-2 vs flash_attn

跳过条件：数值稳定性问题超过 1 周，或 RTX 4090 上实测对实际 seq_len 范围没有收益。

## 七、可用于博客的主题

- **CUDA Graph 的正确姿势**：静态 buffer + copy_()、max_kv_len 固定策略、与 paged attention 的兼容性处理

- **graph pool 设计**：padding 策略 vs 按需捕获的权衡
