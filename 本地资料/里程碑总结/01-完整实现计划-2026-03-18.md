## 范围

### 阶段一：单卡真实推理链路（Phase 1）

目标：`engine.generate(["你好"])` 能在 Ubuntu 实机环境上输出真实 Qwen2.5 文字。

**1.1 接入真实 tokenizer**

- 用 `transformers.AutoTokenizer` 替换 `_tokenize()` 里的 `ord(char)`
- `EngineConfig` 加 `tokenizer_name` 或复用 `model_name`
- 在 `LLMEngine.__init__` 里初始化 tokenizer，decode 时用 `tokenizer.decode()`

**1.2 接入真实模型**

- `ModelRunner.__init__` 接收 `config: EngineConfig`，加载 `AutoModelForCausalLM.from_pretrained()`
- 支持 `dtype=float16`，模型加载后显式 `.to("cuda:0")`
- `prefill()` 用 `model(input_ids=...)` 跑 forward，拿到 `logits` 和 `past_key_values`
- `decode_step()` 用 `model(input_ids=last_token, past_key_values=...)` 做 autoregressive decode
- `past_key_values` 先用 HuggingFace 原生结构（tuple of tensors），不自己管理

**1.3 采样逻辑**

- 从 `logits[:, -1, :]` 取 greedy（temperature=0 时 argmax）
- 支持基础 temperature + top-p sampling
- EOS token 触发 `mark_finished("eos")`

**1.4 HF Baseline Benchmark**

- `benchmark_hf.py`：直接用 `transformers.pipeline` 或原生 `model.generate()`
- 记录：TTFT、TPOT、throughput（tokens/s）、peak GPU memory
- prompt 集合固定，输出长度固定，可复现

**1.5 Mini-Infer Baseline Benchmark（Phase 1）**

- `benchmark_mini.py` 接入真实引擎，记录同样指标
- 此阶段没有 Paged KV Cache 和 Continuous Batching，结果不期待超过 HF

### 阶段二：Paged KV Cache + Continuous Batching（Phase 2）

目标：KV Cache 用块管理，调度器支持动态插入，throughput 相较 HF 有明显提升。

**2.1 真实 KV Cache 数据结构**

- `kv_cache.py`：预分配 GPU tensor `[num_blocks, num_heads, block_size, head_dim]`，对每层分配 K 和 V
- `BlockTable`：每个 request 持有一个 `list[int]`，记录逻辑块到物理块的映射
- `FreeBlockPool`：用 `deque` 管理空闲物理块号
- `init_request()`：从空闲池分配块，填入 block table
- `append_token()`：判断当前块是否已满，满了再从池取新块
- `free_request()`：归还所有物理块

**2.2 Paged Attention**

- `ModelRunner` 不再依赖 `past_key_values`（HF 格式）
- prefill 时，把计算出的 KV 写入 GPU block tensor 对应位置
- decode 时，根据 block table 读取 KV，做 attention
- attention 核心先用 torch `scaled_dot_product_attention` + gather 实现（不上 FlashAttention，先跑通）
- 如有精力，可接入 `flash_attn` 的 `flash_attn_varlen_func` 或 `flash_attn_with_kvcache`

**2.3 Prefill / Decode 分离**

- `Scheduler` 区分 `prefill_batch` 和 `decode_batch`
- prefill batch：只包含刚进来的新请求，跑 prefill forward
- decode batch：所有正在 generate 的请求，批量跑 decode forward
- 每个 step：先 prefill 新请求，再 decode 所有进行中请求（合并到一个 forward 调用）

**2.4 Continuous Batching 调度器**

- 调度循环不再等整个 batch 完成才拉新请求
- 每个 decode step 后，检查空闲块数量；如果足够，从 waiting 队列取新请求加入 running
- preemption：如果显存不足，将低优先级请求的块回收，请求退回 waiting（可选，先实现基础版）
- 关键数据结构：`waiting: deque`、`running: dict[str, RequestState]`、`preempted: deque`

**2.5 Phase 2 Benchmark**

- 同 Phase 1 一样的 prompt 集合和输出长度
- 对比：HF baseline vs mini-infer Phase 1 vs mini-infer Phase 2
- 重点展示：并发吞吐、显存峰值、变长 prompt 处理

### 阶段三：双卡扩展（Phase 3，选做）

目标：在 2×RTX 4090 上跑更高吞吐，作为加分项。

**方案 A（推荐）：Data Parallel Replica**

- 两个独立引擎实例，各占一卡
- 前端做简单 round-robin 或 least-busy 路由
- 实现简单，吞吐直接翻倍

**方案 B（高难度）：Tensor Parallelism TP=2**

- 按 head 分片 Q/K/V attention
- MLP 按 column/row 分片
- 需要 `torch.distributed` 和 nccl all-reduce
- 工程量大，收益不确定，先评估再决定

## 执行顺序

```
Phase 1:
  1.1 tokenizer 接入
  1.2 ModelRunner 真实 forward（prefill）
  1.3 ModelRunner decode_step（past_key_values）
  1.4 采样逻辑（greedy + top-p）
  1.5 engine.generate() 端到端跑通
  1.6 benchmark_hf.py 完整实现
  1.7 benchmark_mini.py 接真实引擎，出第一份数据

Phase 2:
  2.1 KVCacheManager 重写（GPU tensor + BlockTable）
  2.2 ModelRunner prefill 写 KV 到 block tensor
  2.3 ModelRunner decode 读 KV from block tensor（paged attention）
  2.4 Scheduler 改为 Continuous Batching
  2.5 Prefill/Decode batch 分离
  2.6 benchmark 更新，出对比数据

Phase 3（按精力决定）:
  3.1 Data Parallel 双卡方案（推荐先做）
  3.2 评估是否做 TP=2
```

- `engine.generate(["你好，请介绍一下你自己"])` 在 Ubuntu 实机环境上输出真实中文

**Phase 2 完成标志：**

- 新请求可在 decode 循环中动态插入，不需要等上一批结束
- benchmark 显示：throughput 相比 Phase 1 和 HF baseline 有提升，peak memory 更平稳

**最终面试展示标准：**

## 风险与回避方案

| 风险 | 回避方案 |
|------|----------|
| `past_key_values` Phase 1 显存超限 | 限制 max_batch_size=1 先跑通单请求 |
| Paged Attention 手写 attention 性能差 | 先用 `torch.sdpa` 跑正确性，后期接 flash_attn |
| Qwen2.5 模型结构不熟悉 | 先读 HuggingFace 源码中的 `Qwen2Model.forward()` |
| Phase 2 调度器复杂度高，容易引入 bug | 单元测试先覆盖调度状态转移，再跑真实模型 |
| TP=2 工程量失控 | Phase 3 优先做 Data Parallel，TP 作为加分项 |
| GPU 实机环境不可用 | Phase 1 先用 CPU + tiny model 跑通接口，待 Ubuntu GPU 环境恢复后再做真实验证 |
