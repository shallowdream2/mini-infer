## 四、遇到的问题

**1. HuggingFace 下载卡死问题（最耗时）**

`snapshot_download` 在 3.6GB 大文件上的 sha256 校验会挂死 5+ 小时，进程存活但不写盘。
根因：huggingface_hub 某些版本在后台进程中校验 hash 时有 I/O 等待 bug。
解法：确认 `.incomplete` 文件大小等于服务器 `Content-Length`，直接 `cp` 到目标路径。

**2. transformers 版本兼容性**

transformers 5.x 引入了 PyTorch 2.4+ 的 API（`register_pytree_node`），在 PyTorch 2.1.2 上直接崩溃。
Qwen2 支持从 4.40.0 开始，最终锁定 4.43.4。

**3. 串行 decode 的吞吐瓶颈**

当前 `decode_step` 是 `for state in states: model(1 token, past_kv)` 的串行循环。
batch=4 时每个 step 会做 4 次独立 GPU forward，GPU 利用率极低。
这是 Phase 2 的主要改进目标，不是 Phase 1 的 bug。

## 六、下一阶段计划（Phase 2）

Phase 2a — Paged KV Cache + Batch Decode：

1. `kv_cache.py` 完全重写：预分配 GPU block tensor pool + BlockAllocator + BlockTable
2. `model_runner.py` 改写：prefill 写入 paged blocks；decode_step 从 blocks gather KV，合并成一次 batch forward
3. 验收：batch=4 吞吐从 56 tok/s 提升至 ≥ 150 tok/s（HF baseline 是 210）
4. 先用 opt-125m 验证正确性，再接 Qwen2.5-7B 跑 benchmark

Phase 2b — Continuous Batching（下一轮）：
- 调度器改为每 step 动态决定 prefill + decode 组合
- engine.py 主循环重构
