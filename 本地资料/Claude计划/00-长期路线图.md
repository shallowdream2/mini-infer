# 长期路线图

这个文件用于记录从环境搭建到最终博客产出的长期阶段路线。

## 阶段 0：环境与基线

- 确保 Ubuntu + CUDA 环境可用
- 跑通 HuggingFace baseline
- 明确 benchmark 口径
- 产出一篇阶段总结

## 阶段 1：单卡最小推理链路 ✅ 已完成（2026-03-19）

- 真实模型加载（Qwen2.5-7B-Instruct，float16，单卡 RTX 4090，15.7 GB）
- 最小 `generate()`：Prefill + 串行 Decode + EOS 检测
- 单请求与小 batch 跑通
- HF baseline 对比：batch=1 持平（56 tok/s），batch=4/8 差 3.7×/7.3×（串行 decode 导致）
- 产出：里程碑总结、实验记录、博客草稿、知识专题、开发日志、环境配置笔记

## 阶段 2：核心推理机制 ✅ 已完成（2026-03-19）

- `Prefill / Decode` 分离 ✓
- `Paged KV Cache`（BlockTable + FreeBlockPool + block tensor 池）✓
- `Batch Decode`（gather_batch_kv + 左填充 + 一次 batch forward）✓
- `Continuous Batching`（动态准入调度主循环）✓
- benchmark：batch=1/4/8 对比 HF baseline；TTFT 对齐，throughput 达到 HF 的 87.9%（b=1）~49.1%（b=8）
- 主要瓶颈：`gather_batch_kv()` 每步复制 KV 到 dense tensor，Phase 3 需消除
- 产出：里程碑总结、实验记录、博客草稿、知识专题、开发日志、知识笔记

## 阶段 3：性能优化 ✅ 已完成（2026-03-19）

- `gather_batch_kv()` 向量化（PyTorch advanced indexing，消除 Python 循环，batch=8 throughput +79.8%）✓
- `DynamicCache` API 迁移（消除 transformers 弃用 warning，根因在 prefill 不在 decode）✓
- 混合长度 benchmark（8 请求，short × 4 + long × 4，max_new_tokens=256，356 tok/s）✓
- benchmark：batch=8 从 Phase 2 的 49.1% HF → Phase 3 的 88.4% HF
- 残余差距：gather 本身的 KV 复制未消除（需 flash_attn 2.5+ block_tables）
- 产出：里程碑总结、实验记录、博客草稿、知识专题、开发日志、知识笔记

## 阶段 4：双卡扩展 ✅ 已完成（2026-03-19）

- `ReplicaEngine`：两卡各跑完整 LLMEngine，ThreadPoolExecutor 并发，round-robin 分发 ✓
- `TPEngine`：device_map="balanced"（HF Pipeline Parallel），测量用，不集成自定义 KV cache ✓
- benchmark：Replica batch=8 仅 +4.1%（每卡 batch=4 效率接近单卡 batch=8）；PP 吞吐持平，每卡显存减半
- 坑：HF snapshot 不完整触发重下载，需 `HF_HUB_OFFLINE=1` + 根目录路径；tp2 右填充已修复
- 产出：里程碑总结、实验记录、博客草稿、知识专题、开发日志、知识笔记、环境配置记录

## 阶段 5：优化与展示 ✅ 已完成（2026-03-19）

- 量化结论：model_forward 占 97-98%；gather 降到 1.5-1.8%（Phase 3 向量化确认）；residual 12% = DynamicCache 预填充 + 其他系统开销 ✓
- README 从"骨架阶段"全面更新：4 阶段性能数据表、双卡对比、架构说明 ✓
