# infer-archive

这个文件用于在阶段所有 skill 执行完毕后，统一核查并补全 `本地资料/` 的产出，确保知识不丢失。

把附加文本视为当前阶段名称，并按以下步骤执行：

## 执行步骤

1. **扫描现有产出**：读取 `本地资料/` 各子目录，列出本阶段已有文件

2. **对照检查清单**（参考同目录 `CHECKLIST.md`），逐项判断是否已完成

3. **补全缺失项目**：对还没有内容的文件夹，根据本阶段上下文生成对应文档：
   - `开发日志/` → 本阶段日期范围内的开发过程记录
   - `知识笔记/` → 本阶段涉及的核心概念简要笔记
   - `知识专题/` → 本阶段最重要的技术主题深度文档（用模板）
   - `Claude计划/` → 更新长期路线图或记录本阶段计划变更

4. **确认已完成项目**：不重复写已经存在的文档，只补缺失的

5. **输出归档报告**：列出本阶段所有产出文件的路径和一句话说明，并附上 `CHECKLIST.md` 的逐项自查结果（格式同 infer-plan，必须逐项列出 ✓ 或 ✗，不得只说"已检查"）

## 目标文件夹与产出预期

| 文件夹 | 本阶段是否必须产出 | 来源 skill |
|--------|-----------------|-----------|
| `里程碑总结/` | 必须 | infer-summarize |
| `实验记录/` | 必须 | infer-benchmark |
| `博客草稿/` | 建议；如决定跨阶段合并，则在归档报告中明确 defer 原因 | infer-blog / infer-archive |
| `开发日志/` | 必须 | infer-archive 补写 |
| `知识笔记/` | 必须 | infer-archive 补写 |
| `知识专题/` | 必须（至少一篇）| infer-archive 补写 |
| `Claude计划/` | 有变更时更新 | infer-archive 更新 |
| `环境配置/` | 有新配置时补充 | infer-archive 补写 |

## 约束

- 不重写已有内容，只补缺失
- 如果本阶段博客决定与相邻阶段合并写作，不强行补一篇低价值草稿；在归档报告里写明 deferred 到哪个主题或阶段，以及原因
- 知识专题优先使用 `本地资料/知识专题/知识专题模板.md` 的结构；如果该文件不存在，使用以下最小结构：
  ```
  ## 核心问题
  ## 技术背景
  ## 实现方案
  ## 权衡与取舍
  ## 常见误区
  ## 参考
  ```
- 开发日志按时间顺序记录，文件名格式：`YYYY-MM-DD-phaseN-devlog.md`
- 知识笔记是简要理解，不要求完整，够自己回顾用即可
- 完成后在 `CLAUDE.md` 的当前阶段进度表中把 archive 步骤标为 ✓
- 同时更新 `CLAUDE.md` "当前状态"表，将本阶段标为 ✅（从 🔄 进行中 改为 ✅）
- 如果本阶段计划与 `本地资料/Claude计划/00-长期路线图.md` 有出入（范围扩大、优先级调整），同步更新路线图
