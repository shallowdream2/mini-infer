# infer-blog

这个文件用于为当前项目撰写高质量技术博客草稿。

把附加文本视为博客主题，并遵守这些要求：

## 写作前必做

1. **读实验记录**：先读 `本地资料/实验记录/` 中本阶段的 benchmark 文件，以文件中的数字为准，**禁止凭记忆引用数据**
2. **读里程碑总结**：读 `本地资料/里程碑总结/` 中本阶段的总结，确认遇到的坑点和关键决策
3. **读核心代码**：博客涉及哪些模块，读对应的源文件，确保代码示例准确

## 写作要求

- 只写基于真实实现、真实实验和真实问题的内容
- 必须包含背景、问题定义、方案、实现、实验、坑点和总结
- 不写模板化、空泛、流水账式文章
- 如果证据不足，先指出缺什么，再决定是否成文

如果用户要求落盘，默认写入 `本地资料/博客草稿/`。
写作质量要求优先参考同目录下的 `QUALITY_CHECKLIST.md`。

## 完成后

完成输出后，**必须在输出末尾附上 QUALITY_CHECKLIST.md 的逐项自查结果**，格式如下：

```
## 自查结果（QUALITY_CHECKLIST.md）

- [x] 文章主题对应真实项目阶段或真实技术问题
- [x] 结构覆盖：背景、问题定义、方案设计、实现细节、实验结果、坑点反思、总结
- [x] 有明确背景和问题定义
- [x] 有设计取舍，而不是只罗列概念
- [x] 有代码、实验或运行结果支撑
- [x] 有失败点、坑点或反思
- [x] 语言克制、专业、可发表
- [ ] ...（若某项未满足，说明原因或需要补充什么）
```

不得只说"已按清单检查"，必须逐项列出 ✓ 或 ✗ 及原因。

CHECKLIST 自查通过后，在 `CLAUDE.md` 的当前阶段进度表中将 `infer-blog` 步骤标为 ✓。
