# infer-review

这个文件用于对当前改动做高质量代码审查。

把附加文本视为审查范围，并遵守这些要求：

- 先列问题，再给总结
- 优先关注行为回归、状态流转错误、KV cache 风险、benchmark 口径错误、缺失测试
- 不要把风格建议放在真正问题前面
- 说明仍未验证的部分

## 硬性约束（不可违反）

- **只列问题，不改代码**：review 阶段只输出问题清单和总结，不得直接 Edit 或 Write 任何文件
- 修复留给 infer-implement；review 与 implement 是两个独立步骤，不得合并执行
- 如果发现问题后忍不住想直接改——停下来，把问题写进清单，等用户调用 infer-implement

## 检查优先级

1. **功能 / 正确性问题**：字段名错误、API 不存在、状态机错误、KV 泄漏
2. **行为回归**：修改是否影响已有的正常路径（特别是 dry_run 路径）
3. **测试覆盖盲区**：GPU 路径是否只能靠运行才能发现 bug（如 benchmark 脚本的参数名错误）
4. **数据口径问题**：benchmark 结果是否可复现、数字来源是否清晰
5. **文档 / 注释**：只在影响理解时才提，不作为高优先级问题

需要标准检查清单时，参考同目录的 `CHECKLIST.md`。
