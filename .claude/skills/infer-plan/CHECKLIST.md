# infer-plan 检查清单

这个文件列出一份合格的阶段计划必须覆盖的检查项，用于 infer-plan 输出前自查。

## 必须包含

### 动机与承接（不得跳过）

- [ ] 明确引用上一阶段发现了什么，导致本阶段要做这件事
- [ ] 如果本阶段修复的是上一阶段已知的技术债，说明"当时为什么没做"

### 前置条件（有外部依赖时必查）

- [ ] 列出所有需要提前安装或验证的外部依赖（如 flash_attn、特定 GPU 驱动）
- [ ] 给出每个依赖的最小验证命令（`python -c "import xxx"` 形式）
- [ ] **未满足前置条件时，不得进入 infer-implement**

### 范围边界

- [ ] 明确列出"要做"和"不做"两个列表，不能只有"要做"
- [ ] 如果本阶段涉及对已有接口的破坏性变更，明确列出受影响的文件和测试

### 执行顺序

- [ ] 拆解为至少 3 个可独立验证的中间步骤（不能只写"实现 X"）
- [ ] 每个步骤给出最小验证方式（跑什么命令、看什么输出）

### 验收标准

- [ ] 至少 2 条可量化的标准（如"batch=8 throughput ≥ 95% HF"，不是"性能提升"）
- [ ] 至少 1 条正确性验证（输出质量或 dry_run 测试通过）
- [ ] 说明在无 GPU 环境下哪些标准可以提前验证，哪些只能在 GPU 实机验证

### 风险与回退

- [ ] 至少列出 2 个主要风险
- [ ] 每个风险对应一个回退方案（不是"小心处理"）

## 质量禁止项

- ❌ 验收标准中不能有"功能正常""测试通过"等模糊描述
- ❌ 不能只说"参考 Phase N-1 的代码"，必须明确说明哪些文件会被改动
- ❌ 如果计划超过 1000 字但执行步骤只有 2 条，说明拆解不够细
